# Hoshimori (星守り) — Spiritual Goods Vending

ตู้ขายของนำโชคจำลอง (พวงกุญแจ / โอมาโมริ / หินคริสตัล) 15 ช่อง
รับเงินสดกับ PromptPay หน้าตาโทน "ครีมวาชิ + แดงฮังโกะ" การ์ดสินค้าขอบเส้นประแดง ไอคอนเส้นประจำสินค้าทุกช่อง (หินคริสตัลใส่สีตามชนิดหิน)
backend เสิร์ฟหน้าเว็บให้เองในตัว เปิดพอร์ตเดียว ไม่ต้องรันสองโปรแกรมแยกกัน

## โครงสร้างไฟล์

```
vending-machine/
├── docker-compose.yml       รันทั้งระบบด้วย docker compose up --build (พอร์ตเดียว)
├── .dockerignore
├── backend/                 Node.js + Express — เสิร์ฟทั้ง API และไฟล์หน้าเว็บ
│   ├── server.js             API เมนู/checkout/หลังบ้าน + เสิร์ฟ frontend/ แบบ static
│   ├── items.js               ข้อมูลสินค้า 15 ช่อง ราคา สต็อก + เซฟลงไฟล์
│   ├── data/state.json         (สร้างเอง) สต็อกและประวัติขาย ลบไฟล์นี้เพื่อรีเซ็ตตู้
│   ├── package.json
│   └── Dockerfile
└── frontend/                 HTML / CSS / JS ล้วน ไม่มี build step
    ├── index.html             หน้าตู้ขายของ
    ├── style.css              หน้าตาทั้งหมด (รวม CSS ของหน้าแอดมินไว้ในไฟล์เดียวกัน)
    ├── script.js               ทุกอย่างของหน้าตู้: เรียก backend, ตะกร้า, ชำระเงิน, อนิเมชัน
    ├── icons.js                ไอคอนเส้น 15 ชิ้น (ใช้แทนรูปสินค้าตอนยังไม่มีรูปจริง)
    ├── admin.html / admin.js   หน้าแอดมิน (เช็คสต็อก เติมของ ดูยอดขาย)
    └── assets/
        ├── items/               วางรูปถ่ายสินค้า .png ที่นี่ (ถ้ามี) ไม่มีจะใช้ไอคอน
        └── promptpay-qr.png     รูป QR PromptPay ที่ใช้แสดงตอนจ่ายเงิน (ไม่มีไฟล์นี้ระบบจะวาด QR จำลองด้วย CSS แทนเอง)
```

## วิธีรัน

ต้องมี Node.js ติดตั้งไว้ก่อน (เวอร์ชัน LTS)

1. เปิด Terminal ที่โฟลเดอร์ `backend/` แล้วรัน `npm install` (ทำครั้งแรกครั้งเดียว)
2. รัน `npm start`
3. เปิดเบราว์เซอร์ไปที่ **http://localhost:3001** — backend เสิร์ฟหน้าเว็บให้เองแล้ว ไม่ต้องเปิด Live Server แยก
4. หลังบ้านอยู่ที่ **http://localhost:3001/admin.html** (PIN เริ่มต้น 1234)

เปลี่ยนพอร์ต:ตั้งตัวแปร `PORT` ก่อนรัน เช่น `PORT=8080 npm start`

## วิธีรันด้วย Docker (ทางเลือกแทนข้อ "วิธีรัน" ด้านบน)

มี Dockerfile และ docker-compose.yml ให้พร้อมแล้ว รันด้วยคำสั่งเดียว:

```
docker compose up --build
```

เปิด **http://localhost:3001** ได้เลย (พอร์ตเดียว ตู้และหลังบ้านอยู่ด้วยกัน ไม่ต้องมี container แยก)

- สต็อก/ยอดขายเก็บใน Docker volume ชื่อ `hoshimori-data` ลบ container แล้วข้อมูลไม่หาย
- รีเซ็ตข้อมูล: `docker compose down -v`
- เปลี่ยน PIN แอดมิน: แก้บรรทัด `ADMIN_PIN=1234` ใน `docker-compose.yml`
- เปลี่ยนพอร์ตที่แม็พออกมา: แก้ `"3001:3001"` ใน `docker-compose.yml` เช่นเปลี่ยนเป็น `"8080:3001"` แล้วเปิด `localhost:8080`
- หยุดระบบ: `docker compose down`

## วิธีใช้ (หน้าตู้)

1. เลือกสินค้า: กดที่การ์ดสินค้า หรือพิมพ์รหัสในช่อง "รหัสสินค้า" (เช่น A1) แล้วกด "เลือก"
   ซื้อได้ทีละ 1 ชิ้น เลือกอันใหม่จะแทนอันเดิม กด "เอาออก" เพื่อยกเลิกที่เลือก
2. เลือกวิธีจ่ายที่แผง Payment Method
   - เงินสด: กดหยอด 1, 5, 10, 20, 50, 100 จนยอดครบ แล้วกดยืนยันการซื้อ ตู้ทอนเงินให้
   - PromptPay: แสดง QR ตามยอด (หมดอายุใน 5 นาที) กด "จำลองว่าจ่ายแล้ว"
     (เปลี่ยนรูป QR ได้เอง: เอาไฟล์รูปไปทับ `frontend/assets/promptpay-qr.png` ชื่อไฟล์ต้องเหมือนเดิม)
3. ซื้อสำเร็จ สินค้าหล่นลงช่องรับสินค้า แล้วมีหน้าต่างสรุปรายการและเงินทอน

## แอดมิน

เปิด `frontend/admin.html` (หรือกดลิงก์ "แอดมิน" ใต้หน้าตู้) ใส่ PIN `1234`
เปลี่ยน PIN ตอนรัน: `ADMIN_PIN=5678 npm start` (Windows PowerShell: `$env:ADMIN_PIN="5678"; npm start`)

- ดูสต็อกทุกช่อง ปรับ +/− หรือกด "เติมเต็ม" (กลับเป็น 5 ชิ้น) และเติมเต็มทุกช่องได้
- สรุปยอดขายวันนี้ ออเดอร์วันนี้ ช่องที่ใกล้หมด/หมด และประวัติขายล่าสุด
- หน้าตู้ดึงสต็อกใหม่ทุก 10 วินาที เติมของแล้วหน้าตู้อัปเดตเอง
- ใช้ได้เมื่อเปิด backend เท่านั้น

## กฎที่มีอยู่ในโค้ดตอนนี้

- ของหมดช่องนั้นกดไม่ได้ (การ์ดขึ้นป้าย "หมด") ซื้อได้ทีละ 1 ชิ้น (backend ตรวจซ้ำอีกครั้ง)
- ยืนยันซื้อไม่ได้ถ้าตะกร้าว่างหรือเงินไม่ครบ
- ทอนเงินหยิบใบใหญ่สุดก่อน (greedy) ชุด 1/5/10/20/50/100 ทอนลงตัวทุกจำนวน
- เปลี่ยนวิธีจ่ายไม่ได้ถ้ามีเงินสดค้างในตู้ ต้องกดคืนเงินก่อน
- QR PromptPay หมดอายุใน 5 นาที และสร้างใหม่ทุกครั้งที่ยอดในตะกร้าเปลี่ยน
- กดยืนยันการซื้อได้ครั้งเดียวต่อรายการ (ปุ่มล็อกระหว่างรอ backend และระหว่างเล่นอนิเมชัน)
- backend ตรวจสต็อกและเงินซ้ำทุกครั้ง ไม่เชื่อค่าจากหน้าเว็บอย่างเดียว
- ตัดสต็อกหลังตรวจผ่านครบทุกรายการเท่านั้น
- ทุกออเดอร์ที่สำเร็จถูกบันทึกลง `backend/data/state.json` สต็อกไม่หายเมื่อรีสตาร์ตเซิร์ฟเวอร์
- แอดมินต้องมี PIN ถูกต้อง และตั้งสต็อกได้เฉพาะจำนวนเต็ม 0-99

## ไอคอน / ใส่รูปสินค้าจริง

ทุกช่องมีไอคอนเส้น (SVG) ประจำตัวอยู่แล้วใน `frontend/icons.js` มีวิธีเปลี่ยนได้ 3 แบบ:

**แบบที่ 1 — ใช้รูปถ่ายจริงแทนไอคอน (ง่ายที่สุด ไม่ต้องแก้โค้ด)**
วางไฟล์รูปชื่อตรงกับรหัสช่อง เช่น `keychain-1.png` ลงใน `frontend/assets/items/` แล้วรีเฟรชหน้าเว็บ (ไม่ต้องรีสตาร์ต backend)
ระบบใช้รูปถ่ายก่อนเสมอ ช่องไหนไม่มีรูปจะใช้ไอคอนเดิม (ดู `frontend/assets/items/README.txt`)
รองรับนามสกุล `.png` `.jpg` `.jpeg` `.webp` และไม่สนตัวพิมพ์เล็ก/ใหญ่ของชื่อไฟล์

ถ้าใส่รูปแล้วยังไม่ขึ้น (ยังเป็นไอคอนอยู่) ให้ตรวจตาม Terminal ที่รัน `npm start`:
ตอนเปิดเซิร์ฟเวอร์จะมีบรรทัดบอกว่า "พบรูปสินค้า N ช่อง: ..." ถ้าไม่มีชื่อช่องที่ใส่รูปอยู่ในนั้น
แปลว่าตำแหน่งไฟล์หรือชื่อไฟล์ยังไม่ตรง (ต้องอยู่ใน `frontend/assets/items/` และชื่อไฟล์ส่วนหน้าต้องตรงกับรหัส เช่น `keychain-1` ไม่ใช่ `A1` หรือ `Keychain 1`)
ไม่ต้องรีสตาร์ต backend ก็ได้ ระบบเช็กไฟล์ในโฟลเดอร์นี้ใหม่ทุกครั้งที่หน้าเว็บโหลดเมนู แค่รีเฟรชหน้าเว็บก็พอ
(บรรทัด "พบรูปสินค้า..." ที่กล่าวถึงข้างต้นจะขึ้นเฉพาะตอนเปิดเซิร์ฟเวอร์ใหม่เท่านั้น ใช้เป็นตัวช่วยตรวจสอบตอนเริ่มติดตั้งรูป)

**แบบที่ 2 — แก้ลายเส้นของไอคอนเดิม**
เปิด `frontend/icons.js` หาบรรทัดที่ตรงกับรหัสสินค้า เช่น `'keychain-1': \`...\`,` ข้างในเป็นโค้ด SVG path ธรรมดา
(ระบบพิกัด 48x48 หน่วย) แก้ตัวเลขในเครื่องหมาย `d="..."` เพื่อขยับเส้น หรือลบ/เพิ่มบรรทัด `<path .../>`, `<circle .../>` ได้เลย
ดูตัวอย่างง่าย ๆ ในตัวแปร `POUCH` ด้านบนไฟล์ (ใช้ซ้ำกับไอคอน omamori ทั้ง 5 อัน) — แก้ที่ `POUCH` จุดเดียวจะเปลี่ยนทั้ง 5 ช่องพร้อมกัน

**แบบที่ 3 — วาดไอคอนใหม่ทั้งอัน**
ไปวาด SVG จากเว็บไซต์ไอคอนฟรี (เช่น Tabler Icons, Heroicons) หรือโปรแกรมวาดเวกเตอร์ แล้วคัดลอกเฉพาะเนื้อ `<path>`/`<circle>` ฯลฯ
มาแทนของเดิมในคีย์นั้น สิ่งที่ต้องคงไว้คือ:
- ไม่ต้องมีแท็ก `<svg>` ครอบ (ตัวไฟล์ `itemIcon()` ใส่ `<svg viewBox="0 0 48 48">` ให้อัตโนมัติแล้ว)
- ใช้ `stroke="currentColor"` (ไม่ใส่สี fill ตายตัว) เพื่อให้ไอคอนเปลี่ยนสีตามธีมอัตโนมัติ
- ขนาดงานวาดควรอยู่ในกรอบ 6–42 หน่วย (เว้นขอบไว้หน่อย) เพื่อไม่ให้ล้นกรอบการ์ด

แก้เสร็จแล้วรีเฟรชหน้าเว็บได้ทันที ไม่ต้องรีสตาร์ต backend (ไฟล์นี้เป็นไฟล์หน้าเว็บล้วน)
